# agy-company 導入・セットアップガイド 📘

このドキュメントでは、仮想組織管理プラグイン **`agy-company`** を Antigravity CLI (AGY) に導入し、運用を開始するまでの手順を初心者エンジニア向けに分かりやすく解説します。

---

## 1. 事前準備（必要な環境）

本ツールを使用するには、以下の環境が必要です：

- **Antigravity CLI (AGY)**: Google DeepMind のエージェント実行環境
- **Docker & Docker Compose**: Webダッシュボードを起動する場合に必要
- **Obsidian**: 成果物やデイリーノートを閲覧・編集するマークダウンエディタ

---

## 2. ワークスペースへの導入手順

プロジェクト（作業ディレクトリ）に `agy-company` プラグインを導入します。

```text
project-root/ (作業ディレクトリ)
├── agy-company/                      <- 本リポジトリ一式
├── .agents/
│   └── plugins/
│       └── company -> ...            <- シンボリックリンク
└── vault/                            <- Obsidian Vault フォルダ
```

### 手順 1: プラグインのシンボリックリンク作成

ターミナルを開き、運用したいプロジェクトのルートディレクトリで以下を実行します：

```bash
# 1. プラグイン用の配置ディレクトリを作成
mkdir -p .agents/plugins

# 2. agy-company の plugins/company へのシンボリックリンクを作成
# （※ agy-company を project-root 直下に配置している場合の例）
ln -sf "$(pwd)/agy-company/plugins/company" .agents/plugins/company

# 3. シンボリックリンクが正しく作成されたか確認
ls -l .agents/plugins/company
```

> **💡 シンボリックリンクとは？**  
> ファイルの実体をコピーするのではなく「ショートカット」を配置する仕組みです。`agy-company` 側でプラグインのアップデートがあった際にも、自動的に最新のコードが参照されます。

### 手順 2: Vault フォルダの準備

成果物やデイリーノートを保存するための `vault` ディレクトリを作成します (作成済み)：

```bash
mkdir -p vault
```

※ お使いの Obsidian アプリでこの `vault` フォルダを「既存の保管庫（Vault）として開く」設定にしておくと、エージェントが作成したノートがリアルタイムにObsidian上で反映されます。

## 3. 初回起動とオンボーディング（セットアップ）

### Step 1: 秘書を呼び出す

Antigravity CLI を起動し、チャットで以下のように入力します：

```text
/company
```
（または「秘書さん、よろしく」と話しかけても起動します）

### Step 2: 4つの質問に答える

専任秘書が着任し、組織を立ち上げるためのヒアリングが行われます：

1. **事業や活動内容 (Business / Activity)**:
   - 例: 個人開発、受託Web制作、チームでのSaaS開発、学習・研究など
2. **目標や日々の困りごと (Goals & Challenges)**:
   - 例: タスク管理が散らかる、技術調査の時間が足りないなど
3. **定期リマインダーの利用有無 (Schedule)**:
   - 朝会やタスク確認の通知を設定するか（※迷ったら「後で設定する（OFF）」でOK）
4. **秘書の言語と口調設定 (Persona & Language)**:
   - 言語: 日本語 / English / バイリンガル
   - 口調プリセット:
     - 🌟 **丁寧・フレンドリー**（標準・明るいパートナー）
     - 🎩 **執事・プロフェッショナル**（礼儀正しい英国風執事）
     - 🤝 **カジュアル・相棒**（開発仲間・フランク）
     - 🎯 **ストイックコーチ**（目標達成コミット・厳格）
     - 🎨 **カスタム**（自由なキャラ設定）

### Step 3: 自動生成されるフォルダ構造（2層アーキテクチャ）

回答が完了すると、以下のフォルダ群が自動生成されます：

```text
project-root/
├── .company/                          # 【Git管理】AI組織の記憶・設定・作業領域
│   ├── AGENTS.md                      # 組織全体のルール（入力内容が反映）
│   └── secretary/
│       ├── AGENTS.md                  # 秘書の口調・ペルソナ設定
│       └── notes/                     # 壁打ち・意思決定ログ
└── vault/                             # 【Obsidian】クリーンな完成物のみ
    ├── 01_Inbox/                      # サブエージェントの納品物・アイデアメモ
    └── 02_Daily/                      # 双方向リンク付きデイリータスク
        └── YYYY-MM-DD.md
```

これで仮想組織の運用が開始されます！🎉

## 4. 日常の運用テクニック

### 1. タスク管理・メモの保存
```text
> 今日のTODOを教えて
> 「新機能の要件定義」を今日のタスクに追加して
> アイデアを思いついた。「AIを使った議事録要約ツール」
```
- タスクは `vault/02_Daily/YYYY-MM-DD.md` に、メモは `vault/01_Inbox/` に即時反映されます。

### 2. サブエージェントへの業務委譲 (`invoke_subagent`)
```text
> リサーチ部門に、競合サービスの価格調査レポートを作らせて
```
- 秘書がバックグラウンドで専門サブエージェントを起動します。
- 下書きは `.company/research/work/` で行われ、完成レポートのみが `vault/01_Inbox/research/` に綺麗な状態で納品されます。

### 3. 秘書の口調・言語の変更
運用中いつでも秘書のキャラクターを変更できます：
```text
> /company tone
> 秘書の口調を執事風に変えて
> カジュアルな相棒として話して
> Please speak in English
```

## 5. Webダッシュボードの起動 (Docker Compose)

Vault 内のタスクや成果物を視覚的に確認・操作できる Web ダッシュボードが付属しています。

### 起動方法

```bash
# agy-company ディレクトリに移動
cd agy-company

# コンテナをバックグラウンドで起動
docker compose up -d
```

起動後、ブラウザで **`http://localhost:18000`** を開きます。
（※ ローカルホスト専用 `127.0.0.1:18000:3000` に安全にバインドされています）

### 主な機能
- **組織図パネル（常設）**: 組織階層と専門部署カード、Vaultフォルダツリー
- **デイリータスク**: チェックボックスをクリックすると、VaultのMarkdownファイル（`- [ ]` ⇄ `- [x]`）が即時同期
- **成果物一覧**: 部署別フィルタ、「Obsidianで開く」ボタン、メタデータプレビュー
- **⚙️ 設定モーダル**: 日本語／英語のUI言語切り替え、4Kモニター向けの文字サイズ無段階スケーリング

### Vault のパスを変更したい場合（`OBSIDIAN_VAULT_PATH`）
親ディレクトリや任意の場所にある Vault を指定したい場合は、環境変数を指定して起動できます：

```bash
# 例: 親ディレクトリの vault を指定する場合
OBSIDIAN_VAULT_PATH=../vault docker compose up -d
```

## 6. トラブルシューティング

### Q1. `/company` と打っても反応しない
* **確認方法**: ターミナルで以下を実行し、シンボリックリンクが正しい実体フォルダを指しているか確認してください。
  ```bash
  ls -l .agents/plugins/company
  ```
* 矢印（`->`）の先が赤色で点滅している場合、パスが切れています。もう一度 `ln -sf` で正しい絶対パスを指定して再作成してください。

### Q2. 途中で組織をやり直したい・初期化したい
* `.company/` ディレクトリを削除すれば、次回 `/company` 実行時に再び初期オンボーディングからやり直せます：
  ```bash
  rm -rf .company/
  ```

### Q3. ポート 18000 を変更したい
* `agy-company/docker-compose.yml` の `ports` 設定を編集してください：
  ```yaml
  ports:
    - "127.0.0.1:YOUR_PORT:3000"
  ```

## 7. アンインストール（削除方法）

プラグインを削除したい場合は、作成したシンボリックリンクを削除するだけで完了です（元のファイルは消えません）：

```bash
rm .agents/plugins/company
```
